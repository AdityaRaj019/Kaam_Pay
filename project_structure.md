# Kaam_Pay — Project Structure Guide

## 🧐 What is this project?

**Kaam_Pay** is a **freelancing marketplace** (think Fiverr/Upwork) where:

- **Clients** post work and hire freelancers
- **Freelancers** create gigs (services) and take orders
- Payments flow through an escrow system (money held safely until work is done)

---

## 🏗️ The Big Picture — Two Apps in One Repo

```
Kaam_Pay/
├── 🖥️  Frontend  →  Next.js  (what users see in the browser, port 3000)
└── ⚙️  Backend   →  Express  (the server/API, port 5000)
```

They talk to each other: the frontend sends HTTP requests to the backend, which reads/writes to a **PostgreSQL database** via **Prisma**.

## 🖥️ FRONTEND — Next.js (App Router)

### `app/` — Pages & Routes

Next.js uses **folder = URL** routing. Each folder becomes a web page.

```
app/
├── page.tsx              →  / (Home page — landing page)
├── layout.tsx            →  Shared wrapper around ALL pages (navbar, fonts etc.)
├── globals.css           →  Global CSS styles
│
├── (auth)/               →  Auth group (the () means it's just a grouping, not in URL)
│   ├── login/            →  /login
│   ├── register/         →  /register
│   ├── signup/           →  /signup
│   └── verify-email/     →  /verify-email
│
├── dashboard/            →  /dashboard (after login)
├── onboarding/           →  /onboarding (set up your profile)
└── profile/              →  /profile
```

> **Tip:** In Next.js App Router, every folder needs a `page.tsx` to become a real page.

---

---

### `hooks/` — Custom React Hooks

Hooks are functions that manage logic and state in React components.

```
hooks/
└── useAuth.ts    →  Handles login, register, logout, social login (Google/GitHub/Apple)
```

**What `useAuth` does:**

- Calls the backend auth API
- Saves the user info to global state
- Shows success/error toasts
- Redirects to dashboard on login

---

### `store/` — Global State (Zustand)

Like a shared memory that any component can read/write — avoids passing data through many layers.

```
store/
└── auth.store.ts    →  Stores: current user info, isLoggedIn, setUser(), clearUser()
```

Functions that make HTTP requests to your **backend** API.

## ⚙️ BACKEND — Express API (`backend/`)

```
backend/src/
├── server.ts         →  Entry point: starts the HTTP server on port 5000
├── app.ts            →  Express app setup: middleware, routes, CORS, Helmet
│
├── config/
│   ├── prisma.ts     →  Prisma DB client (singleton) — connects to PostgreSQL
│   ├── auth.ts       →  Better Auth server configuration
│   └── cloudinary.ts →  Image upload service config
│
├── modules/          →  Feature modules (each = one domain area)
│   ├── auth/         →  Auth routes: /api/auth/login, /api/auth/register
│   ├── users/        →  User CRUD: /api/users/:id
│   ├── gig/          →  Gig routes: /api/gigs (create, list, search)
│   └── freelancer/   →  Freelancer profile routes
│
├── common/           →  Shared backend utilities (middleware, validators)
├── error/            →  Global error handling middleware
└── types/            →  Backend TypeScript types
```

### How a request flows through the backend:

```
Browser Request
     ↓
  server.ts  (starts listening)
     ↓
   app.ts    (middleware: CORS, JSON parsing, auth)
     ↓
  modules/   (finds the right route handler)
     ↓
  config/prisma.ts  (queries the database)
     ↓
  PostgreSQL DB  (returns data)
     ↓
  JSON Response sent back to browser
```

## 🗃️ DATABASE — Prisma + PostgreSQL

### `prisma/schema.prisma` — Your Database Blueprint

Defines all tables and their relationships.

**Main tables:**
| Model | What it stores |
|---|---|
| `User` | All users (clients + freelancers + admins) |
| `Session` / `Account` | Auth sessions (managed by Better Auth) |
| `Profile` | Freelancer bio, skills, hourly rate |
| `Gig` | Services offered by freelancers |
| `Order` | When a client buys a gig |
| `Payment` | Payment + escrow status |
| `ChatRoom` / `Message` | Messaging between client & freelancer |
| `Review` | Ratings after order completion |
| `Notification` | In-app alerts |

### `lib/generated/prisma/` — Auto-generated Client

Run `npx prisma generate` → Prisma reads your schema and generates TypeScript code you can import to query the DB.

```ts
// Example usage
const gigs = await prisma.gig.findMany({ where: { status: 'ACTIVE' } });
```

## 🔄 How Frontend & Backend Connect

```
Frontend (Next.js :3000)
    │
    │  HTTP Request (via Axios)
    │  e.g. POST http://localhost:5000/api/auth/login
    ↓
Backend (Express :5000)
    │
    │  Prisma query
    │  e.g. prisma.user.findUnique({ where: { email } })
    ↓
PostgreSQL Database
    │
    │  Returns data
    ↓
Backend sends JSON response
    ↓
Frontend updates UI (Zustand store → React re-renders)
```

## 🚀 Running the Project

```bash
# Terminal 1 — Frontend
npm run dev          # → http://localhost:3000

# Terminal 2 — Backend
npm run dev:backend  # → http://localhost:5000
```

> [!TIP]
> Both must be running at the same time for the app to work fully.

> [!NOTE]
> Your local PostgreSQL must also be running with the `kaampay` database created.
